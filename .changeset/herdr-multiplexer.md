**herdr is now a first-class multiplexer next to tmux.** A part can run in a herdr pane and receive its wakes over herdr's socket, with the session lifecycle, the status surfaces and `up` all working there.

**Switch a worktree with `./rr.sh up --use-herdr`, and roll back with `./rr.sh up --use-tmux`.** The flag writes `multiplexer` into `.relayroom/config.json` and then starts that path in the same run; it is not a per-invocation override, because the pager and reboot recovery read the same field and a one-shot flag would migrate a part back to tmux the first time anyone typed a bare `up`.

**Read this before you type it: the flag only exists in an rr.sh generated by this release.** `rr.sh` is written into each worktree and does not update itself, so the order is `npm i -g @relayroom/cli`, then `./rr.sh update --self` in the worktree, then `./rr.sh up --use-herdr`.

**An rr.sh from 0.7.0 or earlier does not reject `--use-herdr` - it ignores it and starts a tmux session.** That generation picked out the flags it recognised and silently dropped the rest, so the command succeeds, the session is tmux, and nothing says otherwise. This bit a user on the day it shipped. There is no way to fix the copies already written; from this release on, an unknown option to `up` or `launch` is an error that names the flag and tells you to regenerate the script. If you have already run it on an old rr.sh, `grep multiplexer .relayroom/config.json` tells you what actually happened - the field will not be there.

Wake delivery over herdr stages the text, verifies it reached the input box, and only then submits, because `agent.prompt` was measured answering a permission dialog on the user's behalf. When the pane is holding a dialog nothing is submitted and nothing is answered: the wake stays queued, a notification tells you once per blocked stretch, and the workspace is marked while it lasts.

The status bar comes back inside the pane as a Claude Code `statusLine` (part, inbox, MCP, pager). It composes with a statusLine you already have - including one set in `~/.claude/settings.json` - rather than replacing it. Each part also gets its own name in herdr's agent list, since a grouped workspace otherwise shows every part under the same label.

**The dashboard now shows which multiplexer is actually delivering, separately from the one that was asked for.** A part whose herdr socket is unreachable falls back to tmux and keeps delivering; that is a degraded state, not a healthy one, and it used to be indistinguishable from a plain tmux part. Migration 0024 adds the two columns; a pager that predates this release reports neither, and that reads as "not reported" rather than as tmux.
